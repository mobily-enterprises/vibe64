# Conversations in a development copy

A host can populate a disposable development environment from an existing workspace.
The host performs this before starting the editor. Copied history remains readable,
but work from the parent starts interrupted, goals and watches paused, and running
background tasks failed. The copy does not stop or modify the parent's work.

Open the copied project and session normally. Review retained pending input before
sending another message: preparation does not replay it. Resume the goal explicitly
when you want it to continue in this test environment. An expired copied AI account
still requires the normal sign-in through **AI Accounts**.

Copied workflows remain stopped even if an outstanding delivery receipt is later
confirmed. Their saved requests and helper history remain available for review.
Lesson conversations saved before Learning v2 keep their original learner and
content bindings and stay read-only; they cannot continue.

Colleague can explain these states and offer supported conversation or goal actions.
History preparation grants no new permissions or shell access. Creating/resetting
the environment uses its host's development workflow. Desktop and mobile use the
same conversation and goal controls.
