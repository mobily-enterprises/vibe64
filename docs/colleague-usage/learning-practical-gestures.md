# Practical lesson steps in Learning mode

Main is the teacher in the selected saved lesson conversation. Colleague remains the general companion in its separate drawer. A passed practical step needs the real workspace action and your explanation to Main; neither starting a lesson nor a diagram alone counts as the action.

## Choose the saved practice project and chat

Turn on **Learning mode** with the yellow L. Start or resume the lesson through Lessons, then use **Practice project** to choose its already prepared saved workspace. This menu lists saved practice targets available to your current learner; it does not install or create another project. A source-less introductory lesson has no practice project entry.

Follow Main's current practical question. Choose the requested practice project yourself, then choose its session or press **Show chat**. Press **App** in Preview when the question asks for the running application. These person clicks retain the selected saved lesson target. Automatic selection after Start or Resume does not count as an independent project-choice step. Answer Main after the actions; do not submit an explanation to Colleague instead.

## Try the application

Wait for the actual App to load. Press **Ask the server** in the application itself and wait for **Hello from the server!** to appear. The displayed reply must belong to that button press in that live Preview frame. Reloaded frames, hidden frames, a failed request, copied text or a diagram do not count. On a phone, keep the App visible and the Colleague body hidden while pressing the application's button. Then return to Main and explain what happened.

## Hide and return to Colleague

For the return-to-Colleague question, minimize the actual Colleague drawer, use the requested workspace control while it is hidden, then restore the same drawer and answer Main. Collapsing Main's chat is not minimizing Colleague. Desktop retains a narrow right drawer; on a phone the Colleague body is full screen or hidden with its launcher available.

Do not start a fresh Colleague conversation midway through this question. If Colleague changed, ask Main to repeat the question and carry out its steps again. Missing or temporarily loading question data does not create a new question or reset the previous drawer identity.

## Recovery and limits

A practical observation can fail while your workspace action remains applied. Repeat that step when the saved session and Preview are ready; do not assume the action was undone. If the learner, lesson target, frame or question changed, return to the intended saved lesson and follow Main's current question. A synthetic click, automatic navigation or an old reply is not practical evidence.

The teacher must genuinely finish delivering the question before practical observations can be accepted. The original server checks the saved lesson pin, native delivery, declared check and your explanation; these controls do not mark a pass themselves. An unavailable exercise or teacher operation must be reported as unavailable instead of granting credit.

Standalone Vibe64 uses its local learner/display scope and the original Colleague component. Hosted Vibe64 uses the signed-in person's authenticated scope. Local routed Colleague navigation is unavailable unless its composing host supplies the original navigation adapter; manual controls and supported server actions remain distinct. Voice is optional and does not replace the practical controls or your explanation.
