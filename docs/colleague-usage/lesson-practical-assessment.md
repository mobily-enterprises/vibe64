# Practical steps and saved lesson results

A practical lesson asks you to carry out an actual task in its prepared project
and explain what happened. Main is the lesson teacher. Colleague can help you
find the lesson, explain supported controls and coordinate authoring, but cannot
ask or grade the teacher's questions on Main's behalf.

Wait for Main's practical question before doing its steps. Use that saved lesson's
actual exercise project and Main session. Starting or resuming a lesson,
automatically showing a project, or an assistant opening a view for you does not
count as an independent project-selection action. If the installation does not
provide the necessary practical controls, report that limit; do not substitute
another project, pretend a control worked or mark the task passed.

For the introduction's workspace practical, select the prepared exercise project,
then reveal its exact Main chat through its session tab or **Show chat**, then
open its visible **Preview**. For the return practical, minimize the real
**Colleague** drawer, use the requested workspace control while its body is
hidden, then restore that same Colleague. Hiding Main is a different action.
On a narrow screen, wait for the requested chat or Preview to be the actual
visible view; a hidden pane does not count.

For the App practical, use the real ready App in Preview. Press its native button
and observe its identified server response, then explain that response to Main.
A diagram, an output label, a claimed response or a supplied screenshot is not
the App interaction. Main's observation uses the existing actual App run and
installed check; the learner cannot choose a terminal, command, origin or pass.

Keep using the same lesson conversation and browser while collecting its steps.
If Main reports accepted partial steps, continue the remaining steps in their
original order. Those facts help coaching; they are not evidence of a completed
task or a saved pass. After the completed observation, send your explanation to
Main in the same conversation. Main uses the actual accepted words, the exact
question and that browser's observation, with the lesson's pinned rubric.
A teacher demonstration or substantial assistance calls for independent follow-up.

Read the saved lesson result before advancing. A check outcome alone is not an
assessment pass. If grading is interrupted, unavailable or uncertain, retain the
same submission identity and inspect saved progress before retrying. Do not run
another inference or repeat an unknown App effect to manufacture success.

A server restart or retired connection can lose unfinished native-step collection;
it does not undo your workspace action. Explain that clearly and repeat the
practical only when collection is genuinely unavailable. Previously confirmed
passes remain in the original saved progress. A new question needs its own real
steps; an older observation cannot be reused for it. Closing a view or minimizing
a drawer is not permission to replace the saved lesson or silently send a message.

Changing assistants or closing a lesson session retires unfinished practical
collection through the same session cleanup. Confirmed results and chat history
remain saved. If stopping or Helper cleanup cannot be confirmed, retry that
operation before starting another assessment; do not assume cleanup succeeded.
